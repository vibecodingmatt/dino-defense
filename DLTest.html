OPEN-SOURCE REVIEW · JULY 2026

          
Why this stack

        

        
The selected components are pinned and served locally. Scanner code can load without a CDN, and license images never leave the page.

      


      

        

          

            SELECTED
            MIT + Apache-2.0
          

          
zxing-wasm + ZXing-C++

          

            The direct reader API exposes PDF417-specific options for local
            crops, binarization, rotation, inversion, downscaling, and denoising.
            Both JavaScript and WebAssembly are pinned and self-hosted.
          

          

            zxing-wasm
          

        


        

          

            EVALUATED
            MIT
          

          
@zxing/browser

          

            A convenient and actively released browser wrapper with a dedicated
            PDF417 reader and direct camera helpers. Its JavaScript decoding core
            is in maintenance mode, so the C++/WASM path was favored for this lab.
          

          

            Project and API
          

        


        

          

            EVALUATED
            Apache-2.0
          

          
html5-qrcode

          

            A widely used turnkey scanner that supports PDF417, cameras, and
            local files. It is a useful rapid-integration option, but is currently
            in maintenance mode and its latest release is several years old.
          

          

            Project and formats
          

        


        

          

            SELECTED PARSER
            Local code
          

          
Spec-derived AAMVA mapping

          

            One small parser handles both barcode paths, preserves unknown elements,
            respects U.S. versus Canadian date order, and covers AAMVA versions
            through the 2025 standard. Current OSS parsers were reviewed but had
            version or date-handling gaps that could distort the experiment.
          

          

            2025 AAMVA standard
          

        



      

    


    

      

        
SUGGESTED PROTOCOL

        
Make the comparison useful

        
    
          
  1. 01
    Control the scene. Use the same device, card, lighting, background, and approximate distance.
    2. 
          
  2. 02
    Alternate methods. Run live, then photo, and repeat for at least ten completed trials per method.
    3. 
          
  3. 03
    Vary one condition. Repeat the set under glare, lower light, older cards, or different phones.
    4. 
          
  4. 04
    Use the measured outcomes. Compare decode success, media-ready time, populated-field count, and payload agreement—not live per-frame misses.
    5. 
        

      

      

        !
        

          
Data capture is not ID verification

          

            PDF417 error correction can recover barcode data, but it cannot prove
            the physical credential is authentic, unaltered, current, or owned by
            the presenter. Do not use this prototype as a fraud decision engine.
